# 텔레그램 연결 메모

## 봇 하나는 한 곳에서만 메시지를 받는다

텔레그램 봇 토큰 하나에는 `getUpdates`(메시지 받기)를 하는 프로그램이 **하나만** 있을 수 있습니다. Claude Code의 공식 텔레그램 플러그인은 시작할 때 이전 수신 프로세스를 밀어내고(`bot.pid`) 자기가 수신권을 가져갑니다.

그래서 이런 일이 생깁니다.

1. 사무실 세션(`claude --channels plugin:telegram@claude-plugins-official`)이 수신 중입니다.
2. 같은 PC에서 **다른 Claude 창**(데스크톱 앱, 다른 프로젝트 터미널 등)을 엽니다.
3. 그 창도 텔레그램 플러그인이 켜져 있으면 수신 프로세스를 새로 띄워 **수신권을 가져갑니다.**
4. 그 창은 `--channels` 로 텔레그램 알림을 받도록 켜진 세션이 아니라서 메시지를 버립니다 → 사무실에는 아무것도 도착하지 않고, 텔레그램에서는 "읽음"만 뜹니다.

원인은 대개 **사용자 전역 설정**(`~/.claude/settings.json`)에서 텔레그램 플러그인이 켜져 있는 것입니다.

```jsonc
// ~/.claude/settings.json  — 이렇게 켜져 있으면 모든 Claude 창이 수신을 가로챌 수 있음
{ "enabledPlugins": { "telegram@claude-plugins-official": true } }
```

## 해결

- 전역 설정에서는 끄고(`false`), **사무실 폴더의 `.claude/settings.json`에서만 켭니다.** 이 프로그램이 만든 사무실은 이미 그렇게 되어 있습니다.
- 대시보드 「연결 · 계정 → 수신 진단」이 이미 떠 있는 가로채기 프로세스를 찾아 정리하고, 전역 설정을 백업한 뒤 꺼 줍니다.
- 한 번 가로채인 동안 온 메시지는 사라졌을 수 있으니 **다시 보내야** 합니다.

## 사무실마다 상태 폴더가 따로 있다

이 프로그램은 사무실을 켤 때 `TELEGRAM_STATE_DIR=<사무실>/.telegram` 을 지정합니다. 그래서

- 사무실마다 **다른 봇 토큰**을 쓸 수 있고(봇 여러 개),
- 토큰(`.env`)과 허용 목록(`access.json`)이 사무실 밖으로 섞이지 않습니다.

같은 봇 토큰을 두 사무실에 넣지 마세요. 위와 같은 충돌이 생깁니다.

## 페어링(내 계정 허용)

봇에게 처음 메시지를 보내면 6자리 코드가 옵니다. 대시보드의 「연결 · 계정」에 코드를 넣으면 `access.json`의 `allowFrom`에 내 텔레그램 ID가 추가되고, 봇이 "연결됐습니다"라고 알려 줍니다. (터미널에서 `/telegram:access pair <코드>` 를 쓰는 것과 같은 동작입니다.) 이 동작은 텔레그램 메시지로는 할 수 없습니다.
