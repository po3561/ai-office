# 스킬 마켓 — 여러 PC가 스킬을 골라서 주고받기

한 PC에서 만든 스킬(텔레그램 지시로 봇이 만든 스킬 포함)을 **내가 고른 것만** 올리면, 같은 마켓에 연결한 다른 PC(메인 PC 등)의
대시보드에서 보고 **내가 직접 눌러서** 설치할 수 있습니다. 대시보드 왼쪽 메뉴 「스킬 마켓」에서 씁니다.

- 공유는 **선택**입니다. 모든 스킬의 기본값은 "이 PC 전용"입니다.
- 설치도 **선택**입니다. 자동 설치·자동 업데이트는 없습니다.
- 공유되는 것은 **스킬 폴더뿐**입니다. `회사정보.md` 같은 업무 데이터, 부서 설정, 봇 토큰, 텔레그램 허용 목록은 대상이 아닙니다.
- 게시·설치·회수는 **대시보드 화면에서만** 됩니다. 텔레그램으로 "이 스킬 마켓에 올려줘"라고 하면 봇은 **게시 요청**만 남기고, 대시보드에서 사용자가 승인합니다(아래 3-1).

## 1. 처음 한 번: 마켓 저장소 만들기

마켓은 **비공개(private) git 저장소** 하나입니다. GitHub를 쓴다면:

```powershell
gh auth login                                  # 처음 한 번 (브라우저 로그인)
gh repo create ai-office-skills --private --description "AI-Office 스킬 마켓"
```

모든 PC에서 같은 저장소를 연결합니다. **비공개로 만드는 것이 중요합니다.** 공개 저장소를 연결하면 화면에 빨간 경고가 뜹니다.

## 2. PC마다: 연결하기

1. 「스킬 마켓 → 연결」에 저장소(`내계정/ai-office-skills`)와 **이 PC의 별칭**(예: 메인PC, 서브PC)을 넣고 「연결하기」.
2. 이 프로그램은 **비밀번호·토큰을 받거나 저장하지 않습니다.** PC에 이미 로그인된 `git`·`gh`를 그대로 씁니다.
   연결이 안 되면 터미널에서 `gh auth login`을 한 번 해 주세요.
3. 게시자 이름은 `git config user.name`입니다. 없으면 `git config --global user.name "이름"`을 실행하세요.

지원하는 저장소 주소: `계정/저장소`(GitHub 약칭), `https://…`, `git@호스트:…`, 공유 폴더에 만든 bare 저장소 경로.
주소에 아이디·비밀번호를 넣는 형태(`https://user:token@…`)는 거절합니다.

## 3. 쓰는 법

| 탭 | 하는 일 |
|---|---|
| 둘러보기 | 마켓의 스킬 검색. 카드에서 「내용 보기 · 설치」 → 검사 결과·파일·SKILL.md 미리보기를 보고 사무실을 골라 설치 |
| 내 스킬 공유 | 사무실별 스킬 목록과 공유 상태. 「마켓에 게시」/「새 버전 게시」/「회수」 |
| 설치된 스킬 | 마켓에서 받은 스킬, 새 버전 업데이트, 제거 |
| 연결 · 설정 | 저장소·별칭 변경, 연결 해제, 연결 상태 |

공유 상태: `비공개(이 PC 전용)` · `게시됨` · `게시 후 바뀜`(새 버전 게시 가능) · `마켓에서 받음` · `기본 스킬`(AI-Office가 넣어 준 스킬이라 공유 안 함) ·
`이름 충돌`(같은 이름을 다른 게시자가 이미 올림) · `공유 불가` · `회수됨`.

**자동 새로고침**: 연결되어 있으면 대시보드 서버가 10분마다 원격의 새 스킬·새 버전 **목록만** 받아 옵니다. 설치·업데이트는 여전히 직접 눌러야 합니다.
새 버전이 있거나 봇의 게시 요청이 있으면 왼쪽 메뉴 「스킬 마켓」 옆에 숫자가 뜹니다. 받아 오기가 실패하면(인터넷·로그인 문제) 마켓 화면 위에 노란 안내가 뜹니다.

**적용 시점**: 설치·업데이트·제거한 스킬은 사무실을 **다시 출근**시킨 뒤부터 적용됩니다(부서와 같습니다).
**제거**는 지우지 않고 사무실의 `보관함\스킬제거\`로 옮깁니다. **업데이트**로 덮어쓰기 전의 내용(내가 고친 부분 포함)은 `보관함\맞춤설정_백업\`에 남습니다.

**한꺼번에 게시**: 「내 스킬 공유」의 사무실 카드 위쪽 「공유 가능한 스킬 모두 게시」를 누르면, 게시할 수 있는 스킬(비공개·게시 후 바뀜)을 한 번에 검사해 보여 줍니다.
빼고 싶은 스킬은 체크를 풀고, 개인정보(⚠️)·위험(🚨) 표시가 있으면 확인란에 체크해야 게시됩니다. 차단 항목(토큰·주민번호 등)이 있는 스킬은 자동으로 제외되고,
다른 게시자의 같은 이름이나 회수된 이름도 제외됩니다. 한 개씩 올릴 때와 같은 검사·확인을 거치며, 버전은 제안된 값(새 스킬 1.0.0, 바뀐 스킬은 +0.0.1)으로 올라갑니다.

### 3-1. 텔레그램에서 게시를 부탁하면 (승인 대기함)

1. 텔레그램: "보고서 서식 스킬 마켓에 올려줘"
2. 봇은 마켓을 직접 건드리지 않고, 사무실의 `업무데이터\마켓요청\<스킬 폴더 이름>.txt`에 요청 이유만 적은 뒤 "대시보드에서 승인해 주세요"라고 답합니다.
3. 대시보드 「스킬 마켓 → 내 스킬 공유」 맨 위 **📱 봇의 게시 요청**에서 「검토 후 게시」(평소와 같은 검사·확인 화면) 또는 「거절」.
4. 게시하거나 거절한 요청 파일은 지우지 않고 `보관함\마켓요청_처리\`로 옮깁니다.

봇이 요청 파일을 아무리 많이 만들어도 **사용자가 대시보드에서 누르기 전에는 아무것도 올라가지 않습니다.**
마켓 연결 전이면 요청은 연결한 뒤에 보입니다.

## 4. 보안 모델

스킬은 문서가 아니라 **AI에게 주는 지시문**(때로는 도구 권한·스크립트)입니다. 그래서 양쪽 모두 검사합니다.

**게시할 때 (내 정보가 새어 나가지 않게)**
- **차단**(게시 불가): 텔레그램 봇 토큰, API 키(sk-, ghp_, AKIA…), 개인 키, 주민등록번호, 카드 번호(검산 통과한 것),
  허용하지 않는 파일 형식(`.exe .dll .zip .svg .html` 등), 링크(바로가기)·너무 큰 파일·너무 깊은 폴더.
- **확인 후 게시**: 전화번호, 이메일, `C:\Users\<이름>` 경로, 비밀번호로 보이는 값, 내 사무실 호칭·이름, 내용을 검사할 수 없는 문서(`.docx .xlsx .pdf .hwp`).
- **위험 표시 후 게시**: 스크립트(`.ps1 .mjs .py …`), 머리말의 `allowed-tools`·`hooks`, 지시 무시·외부 전송·삭제 문구.
- 검사 결과에는 발견한 값을 그대로 싣지 않고 가려서 보여 줍니다.

**설치할 때 (남의 스킬이 위험하지 않게)**
- 항상 미리보기(SKILL.md·파일 목록·검사 결과)를 보고 직접 누른 것만 설치됩니다.
- **위험 표시가 있으면 기본 차단**이고, 확인란을 체크해야 설치됩니다.
- `sha256` 무결성을 다시 계산해 게시된 뒤 바뀐 내용이면 설치하지 않습니다. 회수된 스킬도 설치할 수 없습니다.
- 사무실의 `.claude\skills\<이름>\` 안에만 씁니다. 같은 이름의 스킬이 이미 있으면(마켓에서 받은 것이 아니면) 덮어쓰지 않습니다.
- 설치한 뒤 직접 고친 스킬은 확인 없이 덮어쓰지 않습니다(고친 파일 목록을 보여 주고, 덮어써도 원본은 보관함에 남김).

**접근 권한**: 마켓 접근권은 저장소 접근권입니다. 이 앱은 권한을 주거나 바꾸지 않습니다.

**봇(텔레그램)과의 관계**: 사무실 봇은 마켓을 조회·게시·설치·회수하지 않고, 게시 **요청 파일**만 남길 수 있습니다. 지침(`CLAUDE.md`)에 이 규칙을 넣었고
(예전 버전에서 만든 사무실도 대시보드 서버가 시작할 때 규칙 줄을 자동으로 채워 넣습니다. 사용자가 적은 다른 내용은 그대로 둡니다),
사무실 설정(`.claude/settings.json`)에는 봇이 대시보드 API를 직접 부르는 명령(`x-ai-office`, `/api/offices`, `/api/market`이 든 Bash·PowerShell)을 차단하는 규칙을 넣었습니다.

> **한계(솔직하게)**: 대시보드 서버는 "이 PC 안에서, 대시보드 화면이 보낸 요청"만 받도록 확인하지만(Host·Origin·헤더),
> 같은 PC에서 도는 다른 프로그램이 같은 헤더를 흉내 내는 것까지 완전히 막지는 못합니다. 위 차단 규칙은 봇에 대한 **보조 장치**입니다.
> 그래서 마켓 저장소를 **비공개**로 두고, 신뢰하는 계정만 접근하게 하는 것이 가장 중요합니다.
> 또한 검사는 알려진 패턴을 찾는 것이라 모든 위험을 잡아내지 못합니다. 설치 전 미리보기를 꼭 읽어 주세요.

## 5. 저장소 구조와 형식

```
ai-office-skills/
├─ .gitattributes            "* -text" (줄바꿈 변환으로 해시가 달라지는 것을 막음)
├─ revoked.json              회수 목록 { "<id>": { "reason", "at", "by" } }
└─ skills/<id>/
   ├─ SKILL.md               스킬 본문(머리말 name·description·metadata)
   ├─ (딸린 파일…)            글·이미지·양식만
   └─ .market.json           게시 정보 { schema, id, version, name, description, category, tags,
                                        publisher, sourceAlias, publishedAt, sha256, notes, files, riskLevel }
```

- 인덱스 파일은 두지 않습니다. 목록은 `skills/*/.market.json`을 읽어 만듭니다(두 PC가 동시에 게시해도 병합 충돌이 없도록).
- `id`는 글자·숫자·하이픈(최대 48자), 버전은 `1.0.0` 형식이며 **올리기만** 할 수 있습니다.
- 같은 `id`를 다른 게시자가 올릴 수 없고, 회수된 `id`는 다시 쓸 수 없습니다.
- 제한: 파일당 1MB, 스킬(패키지)당 5MB·60개·폴더 깊이 4.

## 6. 용량

- 스킬은 글 파일이라 작습니다. 이 프로젝트 개발 PC의 실제 스킬: `SKILL.md` 4.7~9.9KB, 스크립트 포함 스킬 하나 약 22KB.
- 100개를 올려도 저장소는 보통 **수 MB**입니다(파일당 1MB·스킬당 5MB 상한). git 이력이 쌓여도 텍스트라 압축이 잘 됩니다.
- 각 PC에는 저장소 **복제본(캐시)** 만 `데이터폴더\market\cache\`에 생깁니다. 지워도 마켓·설치한 스킬에는 영향이 없습니다(연결 해제 시 함께 지움).
- GitHub 저장소 권장 크기(1GB)에는 한참 못 미칩니다.

## 7. 문제 해결

| 증상 | 확인 |
|---|---|
| "git 이 필요합니다" | git 또는 GitHub Desktop 설치. GitHub Desktop의 git도 자동으로 찾습니다. |
| 연결이 안 됨(502) | 저장소 주소 확인 → `gh auth status` → 비공개 저장소면 이 계정에 접근 권한이 있는지 |
| "게시자 이름이 설정되어 있지 않습니다" | `git config --global user.name "이름"` |
| "같은 이름을 다른 게시자가 이미 올렸습니다" | 스킬 폴더 이름을 바꿔서 게시 |
| "다른 PC가 동시에 게시했습니다" | 「새로고침」 후 다시 게시(자동으로 한 번 다시 시도합니다) |
| 설치했는데 봇이 모름 | 사무실을 「다시 출근」시켜야 새 스킬을 읽습니다 |
| "마켓을 새로 불러오지 못했습니다" (노란 안내) | 인터넷 연결 → `gh auth status`(로그인 만료 시 `gh auth login`) → 「새로고침」. 그동안은 마지막으로 받은 목록이 보입니다 |
| 봇에게 올려 달라고 했는데 안 올라감 | 정상입니다. 「내 스킬 공유 → 봇의 게시 요청」에서 직접 승인해야 올라갑니다 |

## 8. 앞으로
